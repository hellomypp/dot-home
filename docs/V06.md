# 도트홈 v0.6 구현·검증 기록

기준: main a5dded9, 2026-11-02. [기획 명세](https://app.notion.com/p/40a26d20896681b8b9f1ed3031ebd172)와 [개발 명세 15절](https://app.notion.com/p/40a26d2089668150b006d5feb6334619)의 P1/P2/P3를 현재 Google OIDC·가족 모델 위에 증분 구현했다.

## 구현

### P1 냉장고 쪽지

게임의 냉장고 클릭 또는 ‘우리 집 냉장고’ → 식료품/쪽지 선택. 쪽지를 붙이면 서버에 저장하고 Phaser가 냉장고 위에 원본 픽셀 포스트잇을 표시한다. 시각 표시는 16px, 터치 영역은 논리 44px이다. 포스트잇을 누르면 쪽지 탭을 연다. 가족 누구나 붙이고 떼어 읽을 수 있으며, 떼면 ATTACHED→TAKEN으로 이동하고 가족 보관함에 남는다. 작성자 또는 대표만 삭제할 수 있다. 작성자·보관자와 시각은 서버의 Membership 식별자로 연결한다.

LifeEvent.NOTE와 다른 테이블/도메인이다. 사물 허용 목록은 현재 fridge 하나다. 모든 조회·변경에 활성 가족 가입을 검사하고, 가구 잠금 + READ_COMMITTED + version으로 동시 떼기 중 하나만 성공시킨다. 재시도는 409와 최신 목록으로 안내한다.

### P2 가족 공유 캘린더

게임 하단 ‘가족 달력’에서 월 탐색, 오늘, 날짜별 목록, 등록·상세·수정·삭제를 제공한다. 일반·생일·기념일, 종일·시간 지정 일정을 지원한다. 활성 가족이 공동으로 편집하며 작성자·수정자는 Principal로 결정한다. 충돌 시 기존 입력을 유지하고 ‘최신 내용으로 다시 열기’를 제공한다.

종일은 LocalDate의 시작·종료 날짜를 **양 끝 포함**으로 저장한다. 시간 지정은 Instant(UTC), 원래 표시 시간대와 분리하며 화면은 Asia/Seoul을 명시한다. 시간 구간은 시작 포함·종료 제외이며 길이 0인 약속은 해당 시점에 표시한다. 자정에 끝난 일정이 다음 날에도 남지 않도록 REST 범위·UI를 함께 검사했다. 조회는 최대 367일, 종료<시작·날짜/시간 혼합·잘못된 시간대를 거부한다. 월별 쿼리는 시간/날짜 인덱스를 이용한다.

### P3 비동기 집들이

대표의 ‘내 계정과 보기 설정’ → ‘집들이 · 친구 방문’에서 링크 생성/취소, 방문자 목록, 방명록 숨김을 제공한다. 링크는 7일 유효하다. 토큰은 SecureRandom 32바이트이며 SHA-256 해시만 DB에 저장한다. 원문 링크는 생성 직후 UI에서만 복사할 수 있고 목록에는 재노출하지 않는다.

친구는 /visit/{token} → Google 로그인 → 원래 목적지 복귀 → ‘방문하기’ 명시적 선택을 거친다. 별도 GuestAccess가 생기며 가족 Membership·실제 가족 수·가족 캐릭터는 바뀌지 않는다. 재방문은 같은 권한을 재사용하고 링크 취소/만료는 기존 방문자에게도 적용한다.

공개 DTO는 householdName, theme, guestbook 세 필드뿐이다. 공통 원본 집 실내 아트를 가족 캐릭터 없이 보여주고 가족의 world·식료품·쪽지·캘린더·활동·계정 식별자를 내려주지 않는다. 방문자는 가족 전용 API/SEND/SUBSCRIBE 권한을 얻지 않는다. 이 버전은 비동기 관람이며 가족의 실시간 위치를 보여주지 않는다.

방명록은 1~1000자 일반 텍스트, CSRF, requestId 재전송 중복 제거, 가구별·계정별 30초 제한을 적용한다. 동시 재전송도 한 건만 남는다. HTML은 실행하지 않고 React 텍스트로 렌더링한다. 대표는 글을 숨길 수 있고 방문자 공개 목록에서 제외된다. 방문 목록의 시각은 해당 링크에 대한 최초 방문 시각이다.

## 공통 보안·실시간

- 요청 DTO에 authorMemberId/userId/householdId 같은 위조 필드를 추가하면 기존 fail-on-unknown-properties 정책으로 400을 반환한다. 경로의 가구 ID도 가입/대표 권한을 별도로 검사한다.
- Google의 state·검증된 OIDC sub·내부 Principal·세션·CSRF는 그대로 사용한다. 반환 허용 경로에 정확한 /visit/43자 토큰만 추가했고 목적지를 Google에 보내지 않는다. 가족 초대 URL 입력 UI는 여전히 /invite만 허용한다.
- OBJECT_NOTE_CHANGED / CALENDAR_EVENT_CHANGED는 DB 커밋 후 기존 가족 topic의 revision과 함께 전송한다. 클라이언트가 world와 관련 쿼리를 다시 읽으며, 재연결 시에도 동일하게 REST로 복구한다. 서버 상태가 원본이다.
- 집들이는 가족 topic을 구독하지 않으며 대표 방명록/방문 목록은 30초 간격 조회와 명시적 변경 후 재조회로 반영한다.
- 비밀값·세션 쿠키·실제 초대 원문 토큰을 커밋하지 않는다. 기존 referrer=no-referrer를 유지한다. Vite 개발 로그의 원문/URL 인코딩 토큰을 제거하고, Nginx 예시에 접근 로그 제외 map을 추가했다. Nginx 템플릿은 실제 배포·nginx -t 검증 전이며 운영 수집기의 오류 로그에도 같은 보호가 필요하다.

- 신규 서버 통합: 두 가족의 쪽지·보관, 동시 떼기, 일정 공유/수정 버전/동시 수정, 자정 경계, 다른 가구 레코드 ID, 방문 Membership 불변, 만료/취소, 방명록 제한·중복·동시 재전송·대표 관리.

- 내장 브라우저에서 실제 QA 세션으로 쪽지 작성, 일정 등록/조회, Phaser 포스트잇 직접 클릭, 대표 링크 생성, 로그아웃→새 방문자 로그인→방문 목적지 복귀→명시 수락→방명록 저장·대표 숨김·공개 목록 제외를 확인했다. fixture/시안 API로 대체하지 않았다.

MySQL 8.4는 V06MySqlIntegrationTest가 같은 기능 통합 테스트를 상속하도록 추가했다. 로컬 Docker 검사는 실행하지 않았으며 실제 GitHub Actions 결과를 별도로 확인한다. 브라우저 QA는 390px 모바일 및 1280px 데스크톱이며, 달력은 375/390/430px에서 가로 넘침 없음과 날짜 셀 최소 44×48px을 [실측](screenshots/v06/layout-checks.json)했다. 이는 실제 iPhone Safari/Google 실계정 E2E를 대신하지 않는다.

## 미검증·제외·후속

- 실제 iPhone Safari의 소프트 키보드·상태바·터치, 두 실제 Google 계정의 전체 집들이 E2E는 미검증이다. 로컬 개발 인증과 OIDC mock 검증을 구분한다.
- 서버 프로세스 재시작 후의 새 도메인 복구는 DB 재조회·마이그레이션 통합 검사와 구분한다. 운영 MySQL 백업/복원 훈련, 장기 부하/대량 데이터 성능 검사는 미수행이다.
- Google Calendar 연동·반복 일정·Web Push, 실시간 방문자 아바타·이동·선물은 제외했다.
- 집 꾸미기 편집 자체가 아직 없으므로 방문자는 현재 공통 실내 아트를 본다. 가족의 실시간 캐릭터나 위치는 의도적으로 표시하지 않는다.
- 후속 우선순위: 실제 iPhone 2계정 검증, 운영 DB 백업/복구, 방문 권한 만료 UX와 방명록 보관 정책 검토. 그 후 반복 일정/꾸미기 공개 범위를 별도 설계한다.

## 사용·실행

기존 실행 명령을 유지한다.

```sh
cd ~/Developer/dot-home
bash scripts/server.sh google
# 별도 터미널
bash scripts/dev.sh
# 또는 Mac/iPhone tailnet 미리보기
python3 scripts/remote-preview.py start
python3 scripts/remote-preview.py status
python3 scripts/remote-preview.py stop
```

Tailscale 연결 후 https://hs-macbook-pro.tailcd16d0.ts.net 에서 본인 집을 연다. 냉장고/가족 달력/대표 계정 메뉴가 진입점이다. 집들이 링크는 가족 입주 링크와 구분해 전달한다. 예전 /studio는 저장되지 않는 아트 시안이므로 새 공유 기능의 실제 검증 장소가 아니다.

추가한 DOT_HOME_API_PORT는 Vite 프록시의 **loopback 대상 포트만** 변경하는 로컬 QA 옵션이다. 기본값 8080, 허용 호스트와 CORS를 확대하지 않는다. QA는 포트 5174→8081의 별도 메모리 DB에서 수행하며 실제 가족 데이터를 초기화하지 않는다.

## CI 및 미리보기 반영

코드 커밋 98ee7a7의 [GitHub Actions 41362627544](https://github.com/hellomypp/dot-home/actions/runs/41362627544)에서 web/server 모두 success를 확인했다. server의 `test mysqlTest bootJar`가 실제 MySQL 8.4에서 기존 11건과 신규 기능 11건을 포함해 통과했다. 이후 집들이 반환 경로의 끝 줄바꿈을 프런트에서도 엄격하게 거부하는 검사를 추가해 로컬 프런트 33건·서버 48건·웹/JAR 빌드를 재확인했다.

기존 미리보기 서버를 정상 종료한 뒤 로컬 DB 파일 3개를 비공개·Git ignore 백업에 복사했다. 서버 재시작에서 Flyway V4~V6의 3개 마이그레이션 성공과 현재 스키마 v6, 앱 시작 완료를 확인했다. HTTPS /studio 200과 googleEnabled=true/devEnabled=false도 재확인했다. 실제 Google 사용자 세션의 새 기능 전체 조작은 사용자의 실기기 확인 대상이다.

격리된 QA를 재현하려면 별도 터미널에서 다음과 같이 실행한다(예시이며 실사용 DB와 분리한다).

```sh
/usr/libexec/java_home -v 21 --exec java -jar apps/server/build/libs/dot-home-server-0.1.0.jar \
  --spring.profiles.active=dev --server.port=8081 \
  --server.servlet.session.cookie.name=DOT_HOME_QA_SESSION \
  '--spring.datasource.url=jdbc:h2:mem:v06qa;MODE=MySQL;DATABASE_TO_LOWER=TRUE;DB_CLOSE_DELAY=-1' \
  --app.origin=http://127.0.0.1:5174
# 다른 터미널
DOT_HOME_API_PORT=8081 bash scripts/pnpm.sh --filter @dot-home/web dev --port 5174
python3 scripts/v06-smoke.py
```

위 메모리 DB는 QA 서버를 중지하면 사라진다. 이번 작업의 QA 프로세스는 검증 후 종료하고 실제 HTTPS 미리보기만 유지한다.
