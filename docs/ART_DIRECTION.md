# 도트홈 — 웹게임 그래픽 제작·적용 지침 v0.5

작성일 / 최종 수정일: 2026-10-31 (Asia/Seoul). 상태: 아트 방향 미확정, 개발 순서 선정.

## 1. 가장 중요한 최신 피드백

사용자는 기존 데모가 생각한 그래픽과 거리가 멀다고 명시했다. 기존 HTML은 기능·동선 참고 자료다. 그 데모의 색상, 사각형 가구, 캐릭터 비율을 최종 아트의 기준으로 삼지 않는다. 확정된 표현은 '쯔꾸루 느낌의 도트 그래픽'이며 정확한 시점·색감·도트 밀도·캐릭터 비율은 아직 정하지 않았다.

Phaser 같은 엔진을 채택한다고 그림의 품질이 자동으로 좋아지지는 않는다. 엔진은 자산을 배치하고 움직이게 하며, 원하는 분위기는 일관된 타일·가구·캐릭터·초상화·애니메이션에서 나온다.

## 2. 그래픽을 적용할 시점

본격적인 기능 확장 전에 대표 집 화면 하나를 목표 품질로 만들고, 이후 기능 개발과 함께 실제 자산을 적용한다. 그래픽 전체를 프로젝트 마지막에 교체하는 계획은 피한다. 캐릭터와 타일 크기는 가구 배치, 길 찾기, 가림 순서, 터치 영역, 화면 확대 방식에도 영향을 주기 때문이다.

| 순서 | 산출물 | 확인할 점 |
|---|---|---|
| 1. 아트 방향 시안 | 같은 집·인물·반려동물을 표현한 비교 가능한 소수 시안 | 사용자가 떠올린 쯔꾸루 감성과 맞는지, 과도하게 미니멀하거나 플라스틱처럼 보이지 않는지 |
| 2. 대표 장면 | 집 한 화면, 사람 2명·반려동물 1마리 예시, 냉장고·소파·창문, 말풍선·얼굴 UI | PC·휴대폰의 실제 브라우저 크기에서 구경하고 싶은지, 정보가 읽히는지 |
| 3. 자산 규격 | 타일·스프라이트·초상화·기준점·충돌 영역 문서 | 이후 다른 공간과 의상을 일관되게 추가할 수 있는지 |
| 4. 기능 통합 | 이동·대기·소파 상호작용·얼굴 선택과 장면 관찰 | 정지 그림뿐 아니라 움직일 때도 품질이 유지되는지 |
| 5. 확장 | 직장·학교·밖, 가구·의상·반려동물 종류 | 확정한 규격과 분위기를 재사용하는지 |
| 6. 마감 | 전환·효과·사운드·성능·접근성 | 읽기와 조작을 방해하지 않는지 |

사람 2명·반려동물 1마리는 대표 장면의 예시 구성일 뿐 제품 제한이 아니다. 시안을 만들기 전에도 로그인·초대·DB와 같은 독립적인 작업은 진행할 수 있지만, 미확정 스타일로 모든 공간의 아트를 대량 제작하지 않는다.

## 3. M0에서 정해야 할 아트 규격

수치는 레퍼런스와 브라우저 시험 결과를 보고 정한다. 16px/32px 같은 타일 크기를 지금 확정한 것으로 기록하지 않는다.

- 시점: 위에서 내려다보는 RPG형인지, 방 내부 단면에 가까운지.
- 캐릭터: 머리·몸 비율, 표정의 최소 표현, 남녀·체형·헤어·의상 조합 방식.
- 반려동물: 사람과의 크기 비율, 종류별 실루엣, 쉬기·이동 표현.
- 환경: 타일 크기, 벽·문·가구 높이, 앞뒤 가림 기준, 그림자의 방향과 색상 수.
- 애니메이션: 방향 수, `idle`·`walk`·`sit` 등 행동 이름, 프레임 크기·수·속도, 기준점.
- 충돌: 보이는 그림 크기와 이동을 막는 바닥 영역의 구분, 소파·냉장고 접근 지점.
- UI: 얼굴 아이콘 크롭, 이름과 장소 표기, 말풍선 위치·겹침 처리, 작은 화면의 터치 영역.
- 자산 관리: 파일명·버전·출처·라이선스·수정 가능 범위, 컬러 팔레트와 예시 장면.

문자 입력·설정·식료품 목록은 읽기 쉬운 일반 UI를 사용할 수 있다. 모든 글자를 작은 픽셀 폰트로 만들어 가독성을 떨어뜨리지 않는다. 도트 감성은 세계와 캐릭터를 중심으로 유지한다.

## 4. 실제 적용 시 품질 확인

- 원본 픽셀을 흐리게 보간하지 않는 확대 방식을 선택하고 화면 배율·기기 픽셀 비율에서 번짐을 확인한다.
- 폭 320~430 CSS px 범위와 태블릿의 대표 화면에서 얼굴 목록·말풍선·하단 조작이 장면을 지나치게 가리지 않는지 확인한다. 이 범위는 초기 확인 기준이며 지원 기기 전체를 뜻하지 않는다.
- 주요 조작 영역은 44 CSS px 이상을 설계 목표로 잡고 실제 손가락 조작을 확인한다. 그림과 터치 영역은 같을 필요가 없다.
- 캐릭터가 가구 뒤·앞을 지날 때 가림 순서와 기준점이 튀지 않아야 한다.
- 방향 전환·행동 전환에서 머리 크기, 의상, 색상이 달라지지 않아야 한다.
- 반려동물이 통로를 막거나 사용자의 말풍선과 UI를 가리지 않게 한다.
- 움직임 감소 옵션과 화면 비활성 시 렌더링 조절을 검토한다. 성능 목표는 실제 지원 기기를 정한 뒤 측정값으로 기록한다.

## 5. 자산 제작 경로

직접 제작·전문 아티스트 협업·상업 사용 가능한 타일셋·AI 시안 생성은 모두 후보이다. 현재 제작 경로와 예산은 미정이다. 외부 에셋은 출처와 사용 조건을 기록하고, 서로 다른 세트의 원근·색·도트 밀도가 맞는지 확인한다.

이미지 생성은 분위기 탐색에 유용할 수 있으나 결과 한 장이 곧바로 타일맵과 일관된 보행 스프라이트가 되지는 않는다. 타일 분리, 투명 배경, 프레임 일관성, 기준점과 충돌 영역 정리가 별도로 필요하다. 기존 게임의 고유 캐릭터나 무단 추출 자산을 사용하지 않는다.

## 6. 현재 상태와 다음 결과물

이 문서는 아트 제작 지침이며 새 아트나 최종 그래픽은 아직 제작하지 않았다. 다음 개발 작업의 첫 결과물은 '원하는 분위기를 찾기 위한 시안 + 실제 크기로 움직이는 집 한 장면'이다. 스타일 검토 결과와 선택 이유를 이 문서에 추가한 다음 다른 공간으로 확장한다.

## 7. 웹플랫폼 v0.5 적용 조건

- 설치 없이 브라우저에서 실행하는 Phaser 장면과 React UI에 자산을 적용한다. 앱 전용 화면을 기본 산출물로 삼지 않는다.
- PC의 넓은 화면·태블릿·모바일에서 화면 구성과 확대 방식을 함께 검토한다. 작은 화면에서 모든 공간을 무조건 축소해 글자와 캐릭터를 읽지 못하게 하지 않는다.
- 마우스·키보드·터치, 입력 폼 포커스, 화면 회전·크기 변경, 캔버스 배율과 픽셀 번짐을 확인한다.
- 첫 대표 장면에 쓰는 사람 2명·반려동물 1마리는 아트 테스트 fixture다. 실제 서비스의 미가입 구성원 표시 규칙을 바꾸지 않는다.
- 그림을 새로 제작하는 단계는 이 패키지를 받은 Codex의 M0다. 이번 지침 수정에서 새 이미지를 제작하거나 최종 아트를 확정하지 않았다.
